# Local Knowledge AI

Пет-проект локальной RAG-системы (Retrieval-Augmented Generation) для поиска информации по внутренней базе знаний и формирования ответов на вопросы пользователя.

Система использует семантический поиск для извлечения релевантных фрагментов документов, передаёт найденный контекст локальной языковой модели и формирует ответ на его основе.

Основная цель проекта — изучить принципы построения RAG-системы на практике: подготовку документов, разбиение на фрагменты, создание эмбеддингов, векторный поиск, генерацию ответов и оценку качества поиска.

Проект также включает эксперименты с различными подходами к поиску и подготовке данных.

> **Результат:** работающий пайплайн, recall@3 = 23/23 на holdout-наборе, 6 экспериментов с зафиксированными выводами.

## Стек

- Python
- [LM Studio](https://lmstudio.ai/) — локальный сервер (`http://127.0.0.1:1234/v1`, OpenAI-совместимый API)
  - эмбеддинги: `text-embedding-qwen3-embedding-0.6b` (размерность 1024)
  - генерация: `google/gemma-4-12b-qat`
- Qdrant (локальный режим, `./qdrant_local_db`)
- LangChain Text Splitters, markitdown, PyYAML

## Пайплайн

```
Doc/*.docx → Doc/Md/*.md → чанки → эмбеддинги → Qdrant → top-3 → LLM
```

1. `docx_to_md.py` — конвертация `.docx` в Markdown (`Doc/` → `Doc/Md/`).
2. `chunker.py` — разбиение документов на чанки:
   - таблицы между метками `TABLE_OPEN` / `TABLE_CLOSE` выносятся в отдельные чанки целиком;
   - остальной текст режется по заголовкам (`MarkdownHeaderTextSplitter`), затем `RecursiveCharacterTextSplitter` (`chunk_size=1000`, `chunk_overlap=100`);
   - к каждому чанку добавляются метаданные из YAML-шапки документа.
3. `embedding.py` — получение эмбеддингов чанков через LM Studio.
4. `base.py` — загрузка векторов в Qdrant. Хэш корпуса хранится в `qdrant_local_db/corpus_hash.txt`: если документы не менялись, коллекция не пересоздаётся.
5. `retriever.py` — вопрос пользователя → эмбеддинг → top-3 чанка → системный промпт (`promt.py`) → ответ модели + вывод источников и score.

## Запуск

1. `pip install -r requirements.txt` (Python 3.11+)
2. Запустить LM Studio и загрузить обе модели (эмбеддинги и генерация).
3. Положить `.docx` в `Doc/`, создать папку `Doc/Md/`.
4. `python docx_to_md.py`
5. Вручную подготовить `.md` (см. «Подготовка документов»).
6. `python base.py` — индексация.
7. `python retriever.py` — вопросы к базе.
8. `python .\test\evaluate_rag.py` — оценка retrieval на holdout-наборе.

## Подготовка документов

Конвертация `.docx` → `.md` не завершает подготовку. Два шага делаются вручную:

**YAML-шапка.** Каждый `.md` должен начинаться с метаданных:

```yaml
---
document_id: ...
source: ...
dept: ...
tags: [..., ...]
---
```

Наличие и корректность полей **не проверяются** — файлы размечались вручную, и все они содержат метаданные. `retriever.py` обращается к этим полям напрямую.

**Метки таблиц.** Каждая таблица оборачивается в `TABLE_OPEN` / `TABLE_CLOSE` (каждая метка на отдельной строке). Автоматически нерезаемый вариант найден не был: `RecursiveCharacterTextSplitter` режет строки Markdown-таблиц между чанками, поэтому таблицы забираются до разбиения и сохраняются целиком.

## Проектные решения

**Всегда top-3, без отсечения по score.** Экспериментально не удалось найти надёжный способ отсекать вопросы, на которые база знаний отвечать не должна: у нерелевантных вопросов score бывает таким же, как у релевантных, поэтому порог не работает. Отсечение «мусорных» вопросов отдано системному промпту: если контекст не содержит ответа, модель сообщает, что информации недостаточно.

**Метаданные в тексте для эмбеддинга.** При создании эмбеддинга к тексту чанка добавляется строка с метаданными:

```python
chunk.page_content + "\n" + str(chunk.metadata)
```

Без неё score хуже, а часть документов не находится. Побочных проблем не замечено.

**Защита от инъекций.** Системный промпт трактует содержимое контекста как данные, а не как инструкции.

## Оценка качества

Retrieval оценён на holdout-наборе из 23 вопросов, не использовавшихся при подборе параметров.

- 12 прямых вопросов по содержимому документов;
- 11 перефразированных и неочевидных.

Метрика: **recall@3 = 23/23** — доля вопросов, для которых все ожидаемые документы попали в Top-3.

Запуск: `python .\test\evaluate_rag.py` (требует запущенного LM Studio и проиндексированной базы).

Отдельно вручную проверены 5 вопросов без ответа в базе: модель сообщает о недостатке информации. Автоматизированной оценки качества генерации нет.

## Известные ограничения

- Нет проверки наличия YAML-шапки и обязательных полей.
- `TABLE_OPEN` / `TABLE_CLOSE` расставляются вручную.
- Фиксированный `limit=3`, порога релевантности нет.
- Часть отладочных `print` оставлена намеренно (вывод score, метаданных, источников).
- `base.py` импортирует `embedding.py`, который при импорте запрашивает эмбеддинги всех чанков— side effect при импорте модуля. Это осознанное упрощение для пет-проекта; правильнее было бы вынести расчёт эмбеддингов в функцию.
- Хэш корпуса считается по тексту и метаданным чанков, но не учитывает модель эмбеддингов. При смене модели база не обновится, пока не изменятся документы (нужно вручную удалить `qdrant_local_db/corpus_hash.txt`).


## Данные

Корпус документов **не включён** в репозиторий. Все `.md`-файлы, использовавшиеся при разработке, синтетические: придуманы автором для отладки пайплайна. Названия компаний и организаций в документах и в `evaluation_set.py` использованы как заполнители и не описывают реальные процессы.

Документы не выложены намеренно - они не нужны для демонстрации пайплайна и не должны восприниматься как реальные данные. По той же причине в репозитории нет `qdrant_local_db/` и `corpus_hash.txt`: это производные от корпуса, они пересоздаются скриптами.

Чтобы запустить систему на своих документах:

1. Положите `.docx` в `Doc/` и создайте папку `Doc/Md/`.
2. `python docx_to_md.py` - конвертация `.docx` → `.md`.
3. Подготовьте `.md` вручную: добавьте YAML-шапку и оберните таблицы в `TABLE_OPEN` / `TABLE_CLOSE` (см. «Подготовка документов»).
4. `python base.py` — индексация в Qdrant.
5. `python retriever.py` - вопросы к базе.

Полный порядок запуска, включая установку зависимостей и запуск LM Studio, - в разделе «Запуск». Формат YAML-шапки и требования к метаданным - в разделе «Подготовка документов».
